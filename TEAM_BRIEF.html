Decision context before agent action

ContextProof

Find the public conversation context that matters, resolve what it means, and put one defensible next action under human control.

Our advantage is not “more context.” Our advantage is knowing which context matters before an agent acts.

Decision states

CONFIRMED Evidence aligns
CONFLICT Evidence disagrees
UNKNOWN Evidence is insufficient
ONE WORKING MAGIC MOMENT > TEN GOOD FEATURES Protect the complete question-to-approved-result loop. Everything else is optional.

01 / Product

The exact flow

A real question enters. ContextProof retrieves public conversation context, isolates the signals that matter, and refuses to hide uncertainty before action.

01 User question Real decision, plainly asked.
02 Threads / public context Live or clearly labelled fallback.
03 Relevant signals Only evidence that changes the decision.
04 Decision state CONFIRMED, CONFLICT, or UNKNOWN.
05 One best next action Exactly one, tied to evidence.
06 Human approval Approve or reject before execution.
07 Visible result Outcome, honest UNKNOWN, or failure.
  1. Ask one credible user question in the interface.
  2. Show the source as LIVE THREADS or FALLBACK DATA.
  3. Expose the small set of evidence that materially affects the answer.
  4. Render one decision state with a concise reason.
  5. Present exactly one next action and wait for approval.
  6. After approval, show the result or an explicit failure state.

Shared output contract

source threads | fallback
signals[] claim + evidence
state confirmed | conflict | unknown
next_action exactly one
approval required
result visible | unknown | failed

03 / Acceptance

Definition of Done

Done means one complete, honest workflow that can be demonstrated in under two minutes. A polished partial flow does not pass.

  • 01A real user question starts the flow.
  • 02Threads search runs, or the interface shows a clearly labelled fallback source.
  • 03Retrieved context is normalized into a stable structured shape.
  • 04The result is explicitly CONFIRMED, CONFLICT, or UNKNOWN.
  • 05The system proposes exactly one best next action.
  • 06No action runs before a visible human approval gate.
  • 07Approval produces a visible result, honest UNKNOWN, or explicit failure.
  • 08The complete flow is demonstrable in under two minutes.

06 / Judging

How the build scores

The demo should make each criterion visible without explanation. The workflow is the proof; narration only points to it.

  1. Core Requirements & Functionality

    Show one complete working workflow from a real question through approval to a visible result.

  2. Innovation & Theme Alignment

    Make the surrounding Threads context essential to the agent’s decision, not decorative input.

  3. Technical Execution & Integration

    Use real integrations where proven and explicit UNKNOWN or failure behavior where they are not.

  4. Usefulness & Agentic Experience

    Turn noisy public conversation into one understandable, controllable next action.

07 / Guardrails

Protect the core

Do not spend the event widening the product or fighting one integration past its decision value.

We are NOT building

  • A social listening dashboard
  • A generic summarizer
  • A multi-agent framework
  • A RAG platform
  • An analytics suite
Threads API fallback rule

30-minute hard gate

If live Threads retrieval cannot be proven quickly, stop random API debugging. Switch to a clearly labelled fallback dataset or another available retrieval route.

Preserve the core ContextProof intelligence: relevant signals → decision state → one action → approval → visible result. Never present fallback data as live.
